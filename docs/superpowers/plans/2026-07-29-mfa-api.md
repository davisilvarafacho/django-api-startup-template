# MFA API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar MFA opt-in completo por e-mail, SMS, TOTP e recovery codes, incluindo `PRE_AUTH`, trusted devices e reset administrativo.

**Architecture:** Um domínio MFA próprio persiste fatores e desafios; PyOTP fornece somente o algoritmo TOTP. Backends plugáveis entregam e-mail/SMS, `PRE_AUTH` limita o login incompleto, e services transacionais garantem consumo único e revogação coordenada.

**Tech Stack:** Django 5.2, DRF 3.16, PyOTP, Celery, Fernet sensitive fields, Knox custom token, pytest-django.

## Global Constraints

- Executar depois de `2026-07-29-auth-token-foundation.md` e antes de
  `2026-07-29-password-security-hibp.md`.
- MFA é opt-in e protege somente a API Knox.
- E-mail, SMS e TOTP podem ficar ativos juntos; um fator por tipo.
- O cliente escolhe o fator; nenhum OTP é enviado automaticamente no login.
- Segredo TOTP/telefone cifrados; OTP por HMAC; recovery por hash lento.
- `PRE_AUTH` dura 5 minutos, tem 5 tentativas e nunca acessa API normal.
- Reset de senha deslogado não exige MFA.
- Trusted device dura 30 dias e é revogado por mudança de senha/fator/contato.
